WRITING CONTRACT — FAQ
Reader goal: get a direct answer to a specific question.
Voice: direct and concise. Answer the question in the first sentence, then explain if needed.
Opening: FIRST SENTENCE of every answer must state the answer directly, not background context.
  GOOD: "Use `Workbook.save(path)` to export as XLSX."
  BAD: "Aspose.Cells provides several methods for saving files."
Paragraphs: 1-3 sentences per answer. Longer answers should include a code snippet or link.
Sentence variety: keep answers tight — avoid padding. One strong sentence beats three hedging ones.
Code integration: include code only when the answer involves a specific API call or configuration step. Keep examples minimal (3-8 lines).
Specificity: name exact classes, methods, version numbers, or error messages. "Not yet implemented" is better than "not fully supported".
Required structure:
- Each question is a ### heading containing a question mark
- Each answer is a paragraph block immediately after the heading — never put answer text in the heading
- No closing summary paragraph
Forbidden: do not add a closing summary paragraph that restates the Q&A content. Do not answer questions with "Yes, you can..." followed by a feature list — just show how. Do not start answers with the product name.
