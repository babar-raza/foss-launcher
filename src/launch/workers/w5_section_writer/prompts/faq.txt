## CRITICAL Rules

1. **NEVER redirect to documentation**. Do NOT write answers like "See the documentation",
   "Check the official guide", or "Refer to the API reference". Every answer must contain
   the ACTUAL answer with specific details.
2. **Include code** in at least 40% of answers. When a question involves how to do something,
   show the code inline — do not tell the reader to look elsewhere.
3. **Link to related pages** where helpful for deeper reading. Use these link patterns:
   - Getting started: [Getting Started Guide](../getting-started/)
   - Installation: [Installation Guide](../installation/)
   - Troubleshooting: [Troubleshooting Guide](../../kb/troubleshooting/)
   - API details: [API Reference](../../reference/api-overview/)
   But the answer itself must be self-contained — the link is supplementary, not the answer.

## Format

1. Organize questions into categories: Getting Started, Common Tasks, Troubleshooting, Advanced
2. Each Q&A:
   ### Q: [Specific question phrased as a developer would ask]?
   A: [2-5 sentence answer with concrete details]
3. Reference claims using [claim: CLAIM_ID] markers
4. Minimum 12 Q&A pairs
5. Each answer must be at least 3 sentences with specifics (versions, class names, methods)

## Output Format

Return only the markdown content. Do not include frontmatter or the page title (H1).
