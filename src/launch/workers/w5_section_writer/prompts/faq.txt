## CRITICAL Rules

1. **NEVER redirect to documentation**. Do NOT write answers like "See the documentation",
   "Check the official guide", or "Refer to the API reference". Every answer must contain
   the ACTUAL answer with specific details.
2. **Include code** in at least 40% of answers. When a question involves how to do something,
   show the code inline — do not tell the reader to look elsewhere.
3. **Link to related pages** where helpful for deeper reading. Use these link patterns:
   - Getting started: [Getting Started Guide](../getting-started/)
   - Installation: [Installation Guide](../installation/)
   - Troubleshooting: [Troubleshooting Guide](../../kb/troubleshooting/)
   - API details: [API Reference](../../reference/api-overview/)
   But the answer itself must be self-contained — the link is supplementary, not the answer.

## Format

1. Organize questions into categories: Getting Started, Common Tasks, Troubleshooting, Advanced
2. Each Q&A:
   ### Q: [Specific question phrased as a developer would ask]?
   A: [2-5 sentence answer with concrete details]
3. Reference claims using [claim: CLAIM_ID] markers
4. Minimum 12 Q&A pairs
5. When showing code, put the ENTIRE example in a SINGLE code fence. NEVER split one example across multiple fences separated by explanation text.
6. Each answer must be at least 3 sentences with specifics (versions, class names, methods)

## FORMATTING RULES

Avoid these formatting defects that cause pipeline validation failures:

- **FQ-1 Naked code**: All code — including single commands — must be in a fenced code block with a language tag (e.g., ```python or ```bash). Never write code lines as plain text outside fences.
- **FQ-2 FAQ concat**: Always place a blank line between an answer and the next `### Q:` heading. Never let an answer and the next question appear on the same line.
- **FQ-3 Truncated bullets**: Every bullet point must be a complete sentence ending with a period. Do not end bullets mid-sentence or with dangling words like "is", "of", "for", "with", "the", or a trailing comma.
- **FQ-4 Double heading**: Always place a blank line between a heading and the following paragraph. Never write heading text and paragraph text on the same line (e.g., `## Section NameThe text begins here` is forbidden).
- **FQ-7 Incoherent sentences**: Every sentence must be grammatically complete and logically coherent. Do not repeat the section heading verbatim as the opening sentence of the section body.

## Output Format

Return only the markdown content. Do not include frontmatter or the page title (H1).
