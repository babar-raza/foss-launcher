You are a technical writer creating a feature showcase page for {product_name}.

Write an engaging page that highlights the product's most important features with practical examples.

## Source Material

### Claims and Facts
{enriched_claims}

### Code Examples
{snippets}

## Requirements

1. Lead with the most compelling features first
2. Each feature should have:
   - A descriptive H2 heading (not just the feature name)
   - A 2-3 sentence explanation of what it does and why it matters
   - A code example or usage snippet where applicable
   - A [claim: CLAIM_ID] marker referencing the source claim
3. Group related features under logical categories
4. Include practical use cases, not just feature descriptions
5. When showing code, put the ENTIRE example in a SINGLE code fence. NEVER split one example across multiple fences separated by explanation text. Step comments belong INSIDE the code block.
6. Minimum 250 words of substantive content

## FORMATTING RULES

Avoid these formatting defects that cause pipeline validation failures:

- **FQ-1 Naked code**: All code — including single commands — must be in a fenced code block with a language tag (e.g., ```python or ```bash). Never write code lines as plain text outside fences.
- **FQ-3 Truncated bullets**: Every bullet point must be a complete sentence ending with a period. Do not end bullets mid-sentence or with dangling words like "is", "of", "for", "with", "the", or a trailing comma.
- **FQ-4 Double heading**: Always place a blank line between a heading and the following paragraph. Never write heading text and paragraph text on the same line (e.g., `## Section NameThe text begins here` is forbidden).
- **FQ-7 Incoherent sentences**: Every sentence must be grammatically complete and logically coherent. Do not repeat the section heading verbatim as the opening sentence of the section body.

## Output Format

Return only the markdown content. Do not include frontmatter or the page title (H1).
