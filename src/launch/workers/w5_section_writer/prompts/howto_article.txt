## FORMATTING RULES

Avoid these formatting defects that cause pipeline validation failures:

- **FQ-1 Naked code**: All code — including single commands — must be in a fenced code block with a language tag (e.g., ```python or ```bash). Never write code lines as plain text outside fences.
- **FQ-3 Truncated bullets/prose**: Every sentence must be complete — do not end with dangling words like "is", "of", "for", "with", "to", "only", or articles ("the", "a", "an"). Also avoid semantically incomplete endings like "you want to work." (missing the object of the action) — always ensure the verb has its complement.
- **FQ-4 Double heading**: Always place a blank line between a heading and the following paragraph. NEVER write heading text and paragraph text on the same line (e.g., `## Section NameThe text begins here` is FORBIDDEN). Each heading must be on its own line with a blank line before the next content.
- **FQ-7 Incoherent sentences**: Every sentence must be grammatically complete and logically coherent. Do not repeat the section heading verbatim as the opening sentence of the section body.
