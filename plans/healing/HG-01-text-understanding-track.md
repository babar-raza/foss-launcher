# HG-01 — Text Understanding Track (Dual-Track Architecture)

**Status**: Not Started
**Gap linkage**: G1 (Text Understanding Track not implemented)
**Role**: Senior engineer. Drop-in, production-ready.
**Priority**: Critical

## Context

The humming-greeting-kay plan contains a full spec section titled
"Text & Non-Code Understanding" requiring:

1. A dual-track architecture: Code Understanding Track + Text Understanding Track
2. Text file taxonomy (product overview, getting started, usage guide, API explanation,
   developer guidance, release/change history, architecture note, troubleshooting,
   legal/policy, example narrative)
3. Cross-linking: text sections linked to code entities (APIs, classes, examples)
4. Noise control: filtering badges, autogenerated sections, legal boilerplate
5. Evidence model expansion: text-derived facts carry source path, section heading,
   confidence, linked code entity, downstream usability classification
6. Rewrite-or-enhance decision gate (must be evidence-based)

None of this was implemented. The Understand worker currently reads README content
into `repo_info.readme_summary` (4000 chars) and passes it as a doc context to the
LLM. This is the only text-understanding path. It has no taxonomy, no cross-linking,
no noise filtering, and no structured evidence output.

## Scope

### Fix

1. Assess current text-ingestion path (file discovery, parsing, evidence flow)
2. Make rewrite-or-enhance decision with evidence
3. Implement text file taxonomy classifier
4. Implement structured text evidence extractor

6. Add noise/boilerplate filtering
7. Wire text evidence into `_build_evidence_context()` as a third evidence source

## Hard rules

- Keep `run_extract()` signature unchanged (text evidence folded into existing ProductEvidence)
- Text extractor must fail-open: exception → MissingInfoEntry, not pipeline abort
- No new LLM call for text classification — use deterministic heuristics only
- No new package dependencies without explicit justification
- Text evidence must be deterministic (same repo → same output)
