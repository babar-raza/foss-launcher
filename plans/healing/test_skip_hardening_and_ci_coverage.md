# Architectural Healing Plan: Test Skip Hardening and CI Coverage Recovery

## Executive Summary
This plan closes two test-governance gaps:
1. Opt-in integration/E2E tests are currently skipped by default and can become dead coverage if CI never runs them.
2. Runtime `pytest.skip(...)` usage can hide missing fixtures/artifacts and mask regressions.

Goal: keep intentional local ergonomics while enforcing deterministic, auditable coverage in CI.

## Scope
- In scope:
  - `tests/**` skip policy normalization
  - CI workflow coverage for opt-in suites
  - Skip telemetry/reporting and quality gates
  - Migration of inappropriate runtime skips to explicit failures
- Out of scope:
  - Rewriting test architecture
  - Reducing legitimate platform constraints (for example Windows symlink privileges)

## Current Problems
1. `tests/integration/test_tc_300_run_loop.py` uses `RUN_INTEGRATION_TESTS` gating.
2. `tests/e2e/test_tc_522_pilot_cli.py` uses `RUN_PILOT_E2E` gating.
3. Multiple tests conditionally skip on missing files/artifacts (templates, pilot config, ruleset, report), mixing optional and required preconditions.
4. No enforced CI contract proving skip-gated suites run on a regular schedule or manual trigger.

## Healing Principles
1. Keep local default fast and safe.
2. In CI, treat critical skip-gated suites as mandatory in at least one lane.
3. Runtime skip is allowed only for truly optional/external constraints.
4. Missing required fixtures/artifacts must fail, not skip.
5. Every skip must be observable and attributable.

## Target State
1. Integration and E2E suites execute in dedicated CI jobs (manual + scheduled + branch protection where appropriate).
2. Runtime skips are classified and reduced; required-precondition skips are eliminated.
3. CI publishes skip inventory (`-rs`) and fails if disallowed skip reasons appear.
4. Team has a documented skip decision matrix and reviewer checklist.

## Phase 0: Baseline Inventory and Classification
### Deliverables
- Machine-generated inventory of all skip sites:
  - decorators: `@pytest.mark.skipif(...)`
  - runtime: `pytest.skip(...)`
- Classification table with fields:
  - file, test, skip type, reason, category, owner, action

### Categories
- `ENV_OPTIONAL`: optional local-only constraints (acceptable)
- `PLATFORM_LIMIT`: OS/privilege limits (acceptable with reason)
- `MISSING_REQUIRED_FIXTURE`: should be fail
- `ORDER_DEPENDENT_TEST`: should be refactored/fail-fast fixture
- `TEMPORARY_TECH_DEBT`: time-bounded with ticket and expiry

## Phase 1: CI Coverage Lanes for Skip-Gated Suites
### Add workflows (`.github/workflows/`)
1. `tests-integration.yml`
   - Trigger: `workflow_dispatch`, `schedule`, optional PR label trigger
   - Env: `RUN_INTEGRATION_TESTS=1`
   - Command: `pytest -q -rs tests/integration/test_tc_300_run_loop.py`
2. `tests-e2e-pilot.yml`
   - Trigger: `workflow_dispatch`, nightly/weekly `schedule`
   - Env: `RUN_PILOT_E2E=1`
   - Command: `pytest -q -rs tests/e2e/test_tc_522_pilot_cli.py`

### Policy
- Required checks:
  - For mainline merges, at minimum integration lane required.
  - E2E lane required for release branches or nightly gate.

## Phase 2: Runtime Skip Remediation
### Rules
1. If file/artifact must exist in repo, replace `pytest.skip(...)` with `assert path.exists(), "..."`
2. If precondition is generated by another test, move setup into fixture and fail when generation fails.
3. Keep skip only when environment is genuinely optional/external and non-deterministic.

### Priority fixes
1. `tests/unit/models/test_ruleset.py`
   - `ruleset.v1.yaml not found` -> fail (repo contract)
2. `tests/unit/models/test_run_config_ingestion.py`
   - missing pilot config -> fail (repo contract)
3. `tests/unit/workers/test_w4_docs_token_generation.py`
   - `No template files found` -> fail or fixture-backed minimal template under test assets
4. `tests/e2e/test_tc_522_pilot_cli.py`
   - `E2E report not available` -> fixture/setup inside test module; fail if setup step breaks

## Phase 3: Skip Policy Guardrail
### Add script
- `scripts/check_test_skips.py`
  - Parse pytest skip report (`pytest -rs`)
  - Enforce allowlist patterns for acceptable reasons
  - Fail on disallowed categories (for example missing required fixture)

### CI wiring
- Run after each test lane and upload:
  - raw pytest output
  - normalized skip report JSON

## Phase 4: Test Structure Hardening
1. Remove order-dependence in E2E module by using fixture-scoped setup artifact generation.
2. Add explicit markers:
   - `@pytest.mark.integration`
   - `@pytest.mark.e2e`
   - `@pytest.mark.requires_network` (if needed)
3. Ensure marker use is deterministic and documented in `pyproject.toml`.

## Phase 5: Governance and Reviewer Controls
1. Add `tests/SKIP_POLICY.md` with:
   - allowed skip categories
   - forbidden skip categories
   - examples and required reason format
2. PR checklist update:
   - “Any new skip includes category + ticket + expiry (if temporary).”
3. CODEOWNERS/reviewer routing for changes touching `tests/**` skip behavior.

## Verification Plan
1. Inventory:
   - `rg -n "@pytest\\.mark\\.skipif|pytest\\.skip\\(" tests`
   - output archived as artifact
2. CI lane proof:
   - integration job run with `RUN_INTEGRATION_TESTS=1`
   - E2E job run with `RUN_PILOT_E2E=1`
3. Skip guardrail:
   - `pytest -q -rs ... | scripts/check_test_skips.py`
   - must pass with zero disallowed skips
4. Regression check:
   - run default unit suite to ensure local fast path unchanged

## Rollout Strategy
1. Week 1:
   - Phase 0 and Phase 1 merged
   - CI lanes available and green
2. Week 2:
   - Phase 2 high-priority runtime skip conversions
3. Week 3:
   - Phase 3 guardrail enabled in non-blocking mode
4. Week 4:
   - guardrail switched to blocking

## Risk Notes
1. Enabling E2E in CI may increase flakiness/cost.
   - Mitigation: isolate lane, retries only for infrastructure failures, preserve logs/artifacts.
2. Converting skip->fail can surface latent repo/setup drift.
   - Mitigation: staged rollout with explicit ownership of each failure.
3. Order-dependence removal may require fixture refactors.
   - Mitigation: keep changes localized to affected modules first.

## Rollback Plan
1. CI rollback:
   - set new lanes to non-blocking while preserving execution
2. Guardrail rollback:
   - keep report-only mode if false positives exceed threshold
3. Test rollback:
   - revert specific skip->fail commits by file; keep inventory and classification artifacts

## Definition of Done
1. Integration and E2E skip-gated suites run in CI on a defined cadence.
2. No `MISSING_REQUIRED_FIXTURE` runtime skips remain.
3. Skip policy script enforces allowlist and is green in CI.
4. Skip inventory and reasons are visible as CI artifacts.
5. Reviewer checklist/governance documentation is in place.

## Ownership Matrix
1. QA/Testing owner: skip policy, guardrail thresholds.
2. Platform/CI owner: workflows, schedules, required checks.
3. Feature owners: convert skip->fail in owned test modules.
4. Repo maintainer: branch protection and final policy enforcement.
