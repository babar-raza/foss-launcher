## Objective

Eliminate duplicate artifact loads in the W9 Validator. `product_facts.json` and `page_plan.json`
are loaded at lines 1229–1230 for Gate 14, then reloaded again at lines 1259–1266 for Gate 16.
Reuse the already-loaded variables instead of reading from disk twice.

## Required spec references

- `specs/21_worker_contracts.md` — W9 Validator contract; artifact load requirements
- `specs/10_determinism_and_caching.md` — single-read-per-run principle

## Scope

### In scope
- `src/launch/workers/w9_validator/worker.py` lines 1259–1266: replace two `load_json_artifact()`
  calls with references to already-loaded `product_facts` and `page_plan` variables from lines
  1229–1230.

### Out of scope

## Implementation steps

In `src/launch/workers/w9_validator/worker.py`, locate Gate 16 block (around line 1257):

```python
# CURRENT (lines ~1259-1268):
try:
    g16_product_facts = load_json_artifact(run_dir, "product_facts.json")
    site_dir_g16 = run_dir / "work" / "site"
    md_files_g16 = find_markdown_files(site_dir_g16)

    # Load page_plan once for page_role lookup
    g16_page_plan: Dict[str, Any] = {}
    try:
        g16_page_plan = load_json_artifact(run_dir, "page_plan.json")
    except Exception:
        pass
```

Replace with:

```python
# AFTER (reuse already-loaded artifacts from lines 1229-1230):
try:
    g16_product_facts = product_facts  # loaded at line 1229 for Gate 14
    site_dir_g16 = run_dir / "work" / "site"
    md_files_g16 = find_markdown_files(site_dir_g16)

    # Reuse page_plan from Gate 14 load (line 1230)
    g16_page_plan: Dict[str, Any] = page_plan if isinstance(page_plan, dict) else {}
```

**Note**: The outer `try:` block remains unchanged. Only the two `load_json_artifact()` calls are
replaced. The `except ValidatorArtifactMissingError:` at the outer level (for Gate 14, line 1248)
already handles the case where `product_facts` might not be loaded — if Gate 14 skipped due to
missing artifacts, then `product_facts` and `page_plan` will already be empty dicts or have
default values from the exception handler.

**Verify**: Before the Gate 16 block, confirm that `product_facts` is in scope. It is assigned at
line 1230: `product_facts = load_json_artifact(run_dir, "product_facts.json")`. If this threw a
`ValidatorArtifactMissingError`, Gate 14 would have been skipped (line 1248), but the variables
would not be assigned. Add a guard:

```python
g16_product_facts = product_facts if 'product_facts' in dir() else {}
```

Actually: since Gate 14 uses a `try/except ValidatorArtifactMissingError:` block that catches
missing artifacts and continues with `gate_results.append({"name": "gate_14_content_distribution", "ok": True})`,
the `product_facts` variable IS assigned in the try block (line 1230). If the load fails, the
exception propagates to the `except ValidatorArtifactMissingError:` and `product_facts` will be
UNBOUND. To handle this safely:

```python
# Safe reuse with fallback:
g16_product_facts = product_facts if 'product_facts' in locals() else {}
g16_page_plan: Dict[str, Any] = page_plan if 'page_plan' in locals() and isinstance(page_plan, dict) else {}
```

This is the safest form: reuses the in-scope variables when present, falls back to empty dicts when
Gate 14 skipped (identical to the current `except Exception: pass` behavior).

## Failure modes

1. **`product_facts` unbound when Gate 14 skipped** — Detection: `NameError` in Gate 16 block.
   Resolution: `'product_facts' in locals()` guard returns `False`, falls back to `{}`.
   Link: specs/21_worker_contracts.md §validator error isolation.

2. **`page_plan` is a non-dict type** — Detection: `AttributeError` on `.get("pages", [])` in Gate 16.
   Resolution: `isinstance(page_plan, dict)` check; falls back to `{}` otherwise.
   Link: specs/21_worker_contracts.md §artifact schema validation.

3. **Gate 16 receives stale artifact** — Detection: n/a (same run, same in-memory object).
   Resolution: artifacts are loaded once per W9 `run()` invocation. No mutation occurs between
   Gate 14 and Gate 16. Link: specs/10_determinism_and_caching.md.
