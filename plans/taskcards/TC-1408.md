## Failure modes

### Failure Mode 1: Test suite failures
**Detection signal**: pytest exits with non-zero code or shows failures
**Resolution steps**:
1. Review failure output to identify root cause
2. Check if failures are related to Round 1 changes (TC-1401–1407)
3. If critical regression, create blocker issue and halt verification
4. If environmental issue (missing deps, etc.), resolve and re-run
**Spec/Gate link**: Regression contract line 14 (all existing tests pass)

### Failure Mode 2: Pilot exit code non-zero
**Detection signal**: `run_pilot.py` returns exit code != 0
**Resolution steps**:
1. Check `validation_report.json` for gate failures
2. Review stdout/stderr for error messages
3. If W5.5 rejection, this is expected behavior (not a failure)
4. If validator gate failure, investigate root cause
5. Create blocker issue if critical regression found
**Spec/Gate link**: `specs/21_w7_validator.md`, validation_report.schema.json

### Failure Mode 3: W5.5 scores below baseline
**Detection signal**: review_report.json dimension scores < baseline thresholds
**Resolution steps**:
1. Identify which dimension(s) dropped
2. Review issues list in review_report.json for new failures
3. Sample affected pages to understand regression
4. Create blocker issue documenting score drop with evidence
5. Determine if Round 1 changes introduced new issues
**Spec/Gate link**: `specs/12_w5_5_content_reviewer.md`, plan lines 285–287

### Failure Mode 4: Manual inspection finds addressed issues
**Detection signal**: Checklist items fail (issues still present)
**Resolution steps**:
1. Document specific pages and line numbers where issues found
2. Trace back to which TC (1401–1407) should have addressed this
3. Determine if issue is regression or incomplete fix
4. Create blocker issue with reproduction details
5. Consider if issue warrants immediate fix or defer to Round 2
**Spec/Gate link**: Plan lines 288–296 (manual inspection checklist)

### Failure Mode 5: Claim count unexpectedly high/low
**Detection signal**: Claim delta > ±30% from baseline
**Resolution steps**:
1. Review TC-1401 (code claims added) and TC-1402 (claims filtered) logs
2. Check if classification filter too aggressive or not aggressive enough
3. Sample filtered/added claims to verify quality
4. If anomaly detected, create blocker issue
5. Document expected range in evidence report
**Spec/Gate link**: `specs/02_w2_facts_builder.md`, plan lines 96–101
