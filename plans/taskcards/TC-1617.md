## Objective

```python
def _decompose_code_block_into_steps(code_lines, section_heading, ...):
    """Decompose code block into per-statement educational steps."""
    claims = []
    step_order = 1

    # For each logical statement (import, instantiation, method call, save):
    for statement in parsed_statements:
        if statement_type == 'import':
            claim_text = f"Import {module_names} to access {inferred_purpose}"
        elif statement_type == 'instantiate':
            claim_text = f"Create a {ClassName} instance to {inferred_purpose}"
        elif statement_type == 'method_call':
            claim_text = f"Call {method}() to {inferred_purpose}"
        elif statement_type == 'save':
            claim_text = f"Save the result to {format} format"

        claims.append({
            'claim_text': claim_text,
            'claim_kind': 'workflow',
            'source_type': 'readme_technical',
            'step_order': step_order,
            ...
        })
        step_order += 1

    return claims
```

**Key**: Each step gets a `step_order` field for sorting within the workflow.

### Step 2: Workflow metadata enrichment (extract_claims.py)

```python
def _enrich_workflow_claims_with_context(claims: List[Dict], section_heading: str, product_name: str) -> List[Dict]:
    """Add prerequisites, verification, and troubleshooting steps to workflows.

    Args:
        claims: Decomposed step claims
        section_heading: Section name (e.g., "Installation", "Quickstart")
        product_name: Product name

    Returns:
        Enriched claims with context steps added
    """
    enriched = []

    # For installation workflows, add prerequisites
    if 'install' in section_heading.lower():
        enriched.append({
            'claim_text': f"Ensure Python 3.8+ is installed on your system",
            'claim_kind': 'workflow',
            'source_type': 'readme_technical',
            'step_order': 0,  # Prerequisite comes first
            ...
        })

    # Add original steps (with step_order incremented)
    for claim in claims:
        claim['step_order'] += 1  # Shift to make room for prerequisites
        enriched.append(claim)

    # Add verification step after installation
    if 'install' in section_heading.lower():
        enriched.append({
            'claim_text': f"Verify installation by importing {product_name} in Python",
            'claim_kind': 'workflow',
            'source_type': 'readme_technical',
            'step_order': len(enriched),
            ...
        })

    # Add troubleshooting context for common issues
    if 'install' in section_heading.lower():
        enriched.append({
            'claim_text': f"If installation fails, try upgrading pip with: python -m pip install --upgrade pip",
            'claim_kind': 'workflow',
            'source_type': 'readme_technical',
            'step_order': len(enriched),
            ...
        })

    return enriched
```

**Call this after decomposition** in `_extract_section_claims()`.

### Step 3: Merge code_understanding workflows (worker.py)

Update workflow assembly (~lines 668-705):

```python
def _merge_workflows(claim_workflows: List[Dict], cu_workflows: List[Dict]) -> List[Dict]:
    """Merge code_understanding workflows with claim-based workflows.

    Strategy:
    - Prefer README workflows (higher quality, user-authored)
    - Add code_understanding workflows only for NEW workflow types
    - Expand step descriptions with "how to" context
    """
    merged = []
    seen_tags = set()

    # Add README workflows first (higher priority)
    for wf in claim_workflows:
        tag = wf.get('workflow_tag', '')
        merged.append(wf)
        seen_tags.add(tag)

    # Add code_understanding workflows for NEW types only
    for wf in cu_workflows:
        tag = wf.get('workflow_tag', '')
        if tag not in seen_tags:
            # Expand step descriptions
            for step in wf.get('steps', []):
                if 'name' in step:
                    step['name'] = f"How to {step['name'].lower()}"
            merged.append(wf)
            seen_tags.add(tag)

    return merged
```

### Step 4: Synthesize common task workflows (worker.py)

Add new function after workflow merging (~lines 706-750):

```python
def _synthesize_common_task_workflows(product_facts: Dict, claims: List[Dict]) -> List[Dict]:
    """Synthesize workflows for common tasks inferred from product capabilities.

    Args:
        product_facts: Product facts including formats, features
        claims: All claims

    Returns:
        List of synthesized workflow dicts
    """
    synthesized = []
    product_name = product_facts.get('product_name', 'Product')

    # If product supports 2+ formats, synthesize format conversion workflow
    formats = product_facts.get('supported_formats', [])
    if len(formats) >= 2:
        synthesized.append({
            'workflow_tag': 'format_conversion',
            'title': f"Convert between {formats[0]} and {formats[1]} formats",
            'name': 'Format Conversion',
            'description': f'Convert files from {formats[0]} to {formats[1]} using {product_name}',
            'complexity': 'simple',
            'estimated_time_minutes': 5,
            'steps': [
                {'step_num': 1, 'step_id': 'step_1', 'name': f'Load {formats[0]} file'},
                {'step_num': 2, 'step_id': 'step_2', 'name': 'Process content'},
                {'step_num': 3, 'step_id': 'step_3', 'name': f'Save as {formats[1]} format'},
            ],
            ...
        })

    # If API suggests batch processing, synthesize batch workflow
    batch_indicators = ['batch', 'multiple', 'list', 'collection']
    api_claims = [c for c in claims if c.get('claim_kind') == 'api_reference']
    if any(ind in c.get('claim_text', '').lower() for c in api_claims for ind in batch_indicators):
        synthesized.append({
            'workflow_tag': 'batch_processing',
            'title': 'Process multiple files in batch',
            'name': 'Batch Processing',
            ...
        })

    return synthesized
```

## Failure modes

### FM1: Step decomposition creates duplicate claims

**Detection**: Duplicate claim_id warnings in logs, lower-than-expected workflow step counts

**Resolution**:
1. Check `_decompose_code_block_into_steps()` generates unique claim_text per step
2. Verify claim_id computation includes step_order or unique text
3. Review deduplication logic in `deduplicate_claims()`

**Spec**: specs/04_claims_compiler_truth_lock.md (Claim ID generation)

### FM2: Workflow enrichment adds too many steps (>15)

**Detection**: Installation workflow has 20+ steps, making it overwhelming

**Resolution**:
1. Limit enrichment to 1 prerequisite, 1 verification, 1 troubleshooting per workflow
2. Don't add prerequisite/verification for quickstart workflows
3. Cap total steps at 12 per workflow

**Spec**: specs/03_product_facts_and_evidence.md (Workflow complexity)

### FM3: Workflow merging loses code_understanding workflows

**Detection**: Total workflows decrease after merging (e.g., 10 → 6)

**Resolution**:
1. Verify `_merge_workflows()` adds code_understanding workflows when tag is NEW
2. Check deduplication logic uses workflow_tag not workflow_id
3. Ensure existing_tags set is populated correctly

**Spec**: specs/21_worker_contracts.md (W2 workflow assembly)

### FM4: Synthesized workflows have empty steps arrays

**Detection**: `'steps': []` in format_conversion or batch_processing workflows

**Resolution**:
1. Check `_synthesize_common_task_workflows()` populates steps list
2. Verify step_num, step_id, name are all present
3. Ensure at least 3 steps per synthesized workflow

**Spec**: specs/schemas/product_facts.schema.json (Workflow schema)

### FM5: Tests fail due to missing step_order field

**Detection**: `KeyError: 'step_order'` or `AssertionError: step_order not found`

**Resolution**:
1. Verify all decomposed claims have `step_order` field
2. Update `_build_workflow_from_step_claims()` to handle missing step_order gracefully
3. Add default step_order=999 for claims without explicit order

**Spec**: specs/10_determinism_and_caching.md (Required fields)

### FM6: Pilot verification shows regression in claim counts

**Detection**: 3D pilot 2455 → 1800 claims (26% decrease), violates ±30% threshold

**Resolution**:
1. Check decomposition doesn't filter out existing claims
2. Verify enrichment adds claims, doesn't replace them
3. Review `_enrich_workflow_claims_with_context()` appends to enriched list

**Spec**: specs/21_worker_contracts.md (W2 output stability)
