# Taskcard TC-1620 — W2 Best Practices & Performance Extraction

## Objective
Extract 8-12 best practice recommendations and 3-5 performance characteristics from repository content to improve documentation completeness. This addresses the 0% sufficiency for optimization guides and performance benchmarks in generated documentation.

## Problem Statement
Round 8 analysis revealed critical gaps in W2 content extraction:
- **0% best practices coverage**: No extraction of "Use X for Y", optimization tips, or anti-patterns
- **0% performance data**: No benchmarks, scalability limits, or timing characteristics
- **Generic content**: W5 generates placeholder content like "optimize for performance" without specific guidance

This taskcard adds deterministic extraction from 4 sources:
1. README "Best Practices" sections (imperative statements)
2. Code patterns (context managers, decorators, locks)
3. Test benchmarks (performance assertions, scalability limits)
4. LLM analysis (enhanced code_understanding.py prompt)

## Failure modes

### FM1: No best practices found in README
**Detection**: product_facts.json has 0 best_practice claims from README source
**Resolution**:
1. Check if README has "Best Practices" section — if not, this is expected
2. Verify `_SECTION_HEADERS` includes all common variations (tips, optimization, etc.)
3. Verify imperative regex patterns are not too restrictive
4. Fallback to code inference and LLM analysis
**Spec/Gate**: specs/03_product_facts_and_evidence.md (graceful degradation)

### FM2: False positives from code inference
**Detection**: Generic claims like "Use with-statements" appear for libraries that don't use context managers
**Resolution**:
1. Add minimum occurrence threshold (e.g., ≥2 with-statements before generating claim)
2. Filter by file type (skip test files, skip __init__.py)
3. Verify claim is relevant to product domain (use product_name in claim text)
**Spec/Gate**: specs/07_code_analysis_and_enrichment.md (quality over quantity)

### FM3: Performance data extraction fails on test files
**Detection**: 0 performance claims despite having test_benchmark_* functions
**Resolution**:
1. Verify regex patterns match actual test naming conventions
2. Check for alternate patterns: `@pytest.mark.benchmark`, `@timeit`
3. Verify test files are included in repo inventory
4. Fallback to LLM analysis if deterministic extraction fails
**Spec/Gate**: specs/21_worker_contracts.md (artifact completeness)

### FM4: LLM response missing best_practices field
**Detection**: JSONDecodeError or KeyError when parsing LLM response
**Resolution**:
1. Verify LLM prompt includes field definitions in system message
2. Check LLM response for truncation (token limit exceeded)
3. Add graceful fallback: if field missing, set to empty array
4. Log warning for debugging
**Spec/Gate**: specs/03_product_facts_and_evidence.md (LLM reliability)

### FM5: Duplicate best practices from multiple sources
**Detection**: Same recommendation appears 3+ times with different source_file values
**Resolution**:
1. Add deduplication step in worker.py after all extraction
2. Normalize claim text (lowercase, strip punctuation) for comparison
3. Merge sources: keep one claim, add all source_files to citations
4. Prefer README source over code inference (higher quality)
**Spec/Gate**: specs/03_product_facts_and_evidence.md (claim uniqueness)

### FM6: Categorization inconsistency
**Detection**: Same keyword triggers different categories (e.g., "cache" → memory vs speed)
**Resolution**:
1. Define clear category priority: memory > speed > correctness
2. Use keyword sets per category (no overlap)
3. Default to correctness if ambiguous
4. Document category decision logic in function docstring
**Spec/Gate**: specs/07_code_analysis_and_enrichment.md (taxonomy consistency)
