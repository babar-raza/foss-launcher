## Objective

Add Gate 20 (Cross-Page Consistency) to W9 Validator. Three deterministic checks:
1. G20-001: Duplicate prose block >= 100 chars in >= 2 pages → warn
2. G20-002: Conflicting Python/OS version ranges across pages → error
3. G20-003: Same entity with 2+ distinct names → warn

## Required spec references

- `specs/09_validation_gates.md` section Gate 20 Cross-Page Consistency
- `plans/healing/07_cross_section_consistency_checks.md`

## Scope

### In scope

- New file `gate_20_cross_page_consistency.py` with `run_gate_20(md_files)`
- Register in `gates/__init__.py`
- Invoke after Gate 19 in `worker.py` using site directory scan
- 4 unit tests: duplicate-detected, duplicate-clean, version-contradiction, version-clean

### Out of scope

## Implementation steps

1. Create `gate_20_cross_page_consistency.py` with:
   - `run_gate_20(md_files: list[Path]) -> list[dict]` entry point
   - G20-001: collect all paragraphs >= 100 chars per file; detect exact duplicates across files → warn
   - G20-002: extract version patterns (Python X.Y+, requires Python X.Y) per file; detect contradictory ranges → error
   - G20-003: collect entity names from backtick expressions; detect same concept with distinct capitalizations → warn

2. Register in `gates/__init__.py`:
   ```python
   from .gate_20_cross_page_consistency import run_gate_20
   ```

3. In `worker.py`, invoke after Gate 19:
   ```python
   gate_20_issues = run_gate_20(md_files)
   all_issues.extend(gate_20_issues)
   ```

4. Add 4 unit tests in `tests/unit/workers/test_gate_20_cross_page_consistency.py`:
   test_g20_001_duplicate_block_detected,
   test_g20_001_unique_blocks_clean,
   test_g20_002_version_contradiction_detected,
   test_g20_002_consistent_versions_clean

## Failure modes

### FM-1: md_files list is empty or contains unreadable files

**Detection**: `run_gate_20` receives empty list or file.read_text() raises OSError.
**Resolution**: Return empty issues list on empty input; skip unreadable files with WARNING log.
**Spec/gate link**: specs/09_validation_gates.md section Gate 20

### FM-2: Version regex matches non-version text

**Detection**: Over-eager regex captures unrelated numeric strings as version constraints.
**Resolution**: Pattern anchored to explicit keywords ("Python", "requires", "minimum"); unit tests verify false-positive absence.
**Spec/gate link**: specs/09_validation_gates.md section Gate 20 G20-002

### FM-3: Gate 20 error blocks pipeline when only warns expected

**Detection**: G20-002 error issues cause worker to mark run as failed.
**Resolution**: Gate error/pass logic correctly distinguishes error vs warn severity; test verifies gate passes with warn-only output.
**Spec/gate link**: specs/09_validation_gates.md section gate pass/fail criteria
