## Objective

Add Gate 17 to W7 validator: an LLM-based formatting quality check that uses
the same defect checklist as W7 TC-2360 to verify no formatting defects
survived the W7 fix pass. Defense-in-depth: W7 fixes proactively, W7
gates as the final enforcer. LLM-optional — gate passes when LLM unavailable.

## Required spec references

- specs/09_validation_gates.md: Gate contract
- specs/21_worker_contracts.md: W7 worker contract

## Scope

- New file: `src/launch/workers/w9_validator/gates/gate_17_formatting_quality.py`
- Modify: `src/launch/workers/w9_validator/gates/__init__.py` — export gate_17
- Modify: `src/launch/workers/w9_validator/worker.py` — import + execute gate_17
- New test: `tests/unit/workers/test_gate_17_formatting_quality.py`

## Gate logic

- Scans `work/site/content/**/*.md` (published content, not drafts)
- Calls LLM with same format_fixer.txt prompt (from TC-2360)
- Ignores `fixed_content` from LLM response — only reads `defects`
- FQ-1 (naked code), FQ-3 (truncated), FQ-4 (double heading), FQ-7 (incoherent)
  → severity `error` → gate fails
- FQ-2 (FAQ concat), FQ-5 (keyword colon), FQ-6 (claim comments) → severity `warn`
  → gate passes but issues recorded
- Returns `(True, [])` when LLM unavailable (gate is LLM-optional)

## Inputs

- Published markdown files in `run_dir/work/site/content/`
- run_config (for LLM client initialization)

## Outputs

- Gate result (pass/fail) appended to `gate_results` in validation_report.json
- Issues appended to `all_issues` in validation_report.json
