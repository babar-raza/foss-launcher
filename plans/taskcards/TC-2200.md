# Taskcard TC-2200 - Sanitizer Deterministic Fixes

## Objective
Fix three critical content sanitizer bugs preventing publication: (1) headings trapped in code blocks, (2) visible backtick-wrapped claim markers, and (3) malformed URLs with `/./ ` and `/index/` segments.

## Required spec references
- plans/taskcards/00_TASKCARD_CONTRACT.md
- specs/21_worker_contracts.md
- specs/09_validation_gates.md

## Scope
### In scope
- **R17-001**: Fix `fix_prose_in_code_blocks()` to detect ALL heading levels (H1-H6), not just H2
- **R17-002**: Strip backtick-wrapped HTML claim comments (`` `<!-- claim: hex -->` ``)
- **R17-005**: Clean `/./` and `/index/` from absolute URLs in `absolutize_links()`
- Add ~15 new tests covering all three fixes

### Out of scope
- Other sanitizer functions not related to these three issues
- LLM-based content generation changes
- Non-deterministic fixes

## Implementation steps
1. **R17-001**: Update `fix_prose_in_code_blocks()` line 188:
   - Change: `is_heading = stripped.startswith('## ')`
   - To: `is_heading = bool(re.match(r'^#{1,6}\s', stripped))`
   - Rationale: Detect H1, H3-H6 in addition to H2

2. **R17-002**: Update `strip_visible_claim_markers()` line 1256:
   - Add after existing backtick claim strip: `content = re.sub(r'`<!--\s*claim:?\s*[a-f0-9\-]*\s*-->`', '', content)`
   - Rationale: Strip backtick-wrapped HTML claim comments

3. **R17-005a**: Update `_build_absolute()` helper in `absolutize_links()` line 1340:
   - Add `.replace("/./", "/")` to URL normalization chain
   - Rationale: Clean path traversal artifacts

4. **R17-005b**: Add post-processing in `absolutize_links()` after `re.sub()`:
   ```python
   # Clean /index/ from URLs — Hugo serves _index.md at directory root
   content = re.sub(r'(https://[^)]+)/index/(\))', r'\1/\2', content)
   content = re.sub(r'(https://[^)]+)/index(\))', r'\1/\2', content)
   ```

5. Add ~15 test cases in `test_content_sanitizer.py`:
   - H1, H3, H4, H5, H6 inside code fences → rescued
   - Backtick-wrapped HTML claim markers → stripped
   - `/./` in absolute URLs → cleaned
   - `/index/` in URLs → cleaned
   - Mixed scenarios

6. Run full test suite: `PYTHONHASHSEED=0 .venv/Scripts/python.exe -m pytest tests/ -x`

7. Document evidence and self-review

## Failure modes
### FM1: Regex breaks valid code blocks
Detection signal: Tests fail for code blocks containing legitimate `#` characters (comments, directives).
Resolution steps: Refine regex to check context (beginning of line after stripping whitespace).
Spec/Gate link: specs/21_worker_contracts.md (W5 content sanitization)

### FM2: URL cleanup breaks valid paths
Detection signal: Absolute URLs with intentional `/./` or `/index/` segments are malformed.
Resolution steps: Add negative lookahead or context checks to preserve valid patterns.
Spec/Gate link: specs/09_validation_gates.md (Gate 6: Link validation)

Detection signal: Manual pilot inspection reveals edge cases not covered by tests.
Resolution steps: Add missing test scenarios based on pilot output analysis.
