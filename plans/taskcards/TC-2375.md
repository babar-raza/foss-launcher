## Objective

Create `markdown_zones.py` with a zone-aware markdown parser (`parse_zones`, `render_zones`,
`apply_to_prose_zones`). Wrap 5 prose-only sanitizers in `run_pipeline()` with
`apply_to_prose_zones()` to prevent code blocks and frontmatter from being accidentally
modified by prose rules.

## Failure modes

### FM-1: round-trip failure
**Detection**: `render_zones(parse_zones(text)) != text` on edge case input.
**Resolution**: `splitlines(keepends=True)` preserves all line endings exactly;
regex-free zone detection avoids substitution bugs.
**Spec/gate link**: specs/21_worker_contracts.md §Zone-Aware Sanitizer Model

### FM-2: unclosed fence misclassified as PROSE
**Detection**: Content after an unclosed fence fence is incorrectly classified.
**Resolution**: Parser treats unclosed fence as extending to EOF, same heuristic as
the existing `close_unclosed_fences()` sanitizer.
**Spec/gate link**: specs/09_validation_gates.md §Gate 1

### FM-3: regression in sanitizer behavior
**Detection**: Full test suite fails after wrapping sanitizers.
**Resolution**: Additive approach — existing functions unchanged; zone guard only
prevents them receiving CODE_FENCE/FRONTMATTER content, not prose content.
**Spec/gate link**: All existing test_content_sanitizer.py tests must pass.
