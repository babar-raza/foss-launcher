## Objective

Reduce LLM call overhead by (1) reusing HTTP connections via a persistent `requests.Session` pool,
(2) respecting `Retry-After` headers on rate-limit responses, and (3) wiring the already-parsed
`max_concurrency` run_config field to a `threading.Semaphore` so W5 parallel pages cannot
overwhelm the LLM endpoint. All changes are backwards-compatible (zero behavioral change when
`max_concurrency: 0` or absent).

## Implementation steps

### Step 1: http.py — Session Pool

Add module-level session management after existing imports (line 15 area):

```python
import threading
from requests.adapters import HTTPAdapter

_session: Any = None
_session_lock = threading.Lock()

def _get_session() -> Any:
    """Return a thread-safe lazily-initialized persistent HTTP session with connection pooling."""
    global _session
    if _session is None:
        with _session_lock:
            if _session is None:
                try:
                    import requests as _r
                except ImportError:
                    raise ImportError(
                        "requests library required for HTTP clients. "
                        "Install with: pip install requests"
                    )
                s = _r.Session()
                adapter = HTTPAdapter(pool_connections=10, pool_maxsize=20, max_retries=0)
                s.mount("http://", adapter)
                s.mount("https://", adapter)
                _session = s
    return _session
```

In `http_get()`: replace `try: import requests` block → `return _get_session().get(...)`.
In `http_post()`: replace `try: import requests` block → `return _get_session().post(...)`.

**Guarantee D preserved**: `_validate_url()` still runs before `_get_session()` is called.

### Step 2: llm_provider.py — Retry-After Header

In `_call_endpoint()` (around line 531), replace:
```python
if response.status_code != 200:
    raise Exception(f"LLM API error ({response.status_code}): {response.text}")
```
With:
```python
if response.status_code == 429:
    _retry_after = response.headers.get("Retry-After")
    if _retry_after:
        try:
            _wait_s = min(float(_retry_after), 60.0)
            logger.info("rate_limited_retry_after wait_s=%s call=%s", _wait_s, id(request_payload))
            time.sleep(_wait_s)
        except ValueError:
            pass  # Non-numeric header — fall through to default backoff
    raise Exception(f"LLM API error (429 rate limit): {response.text}")
if response.status_code != 200:
    raise Exception(f"LLM API error ({response.status_code}): {response.text}")
```

### Step 3: llm_provider.py — max_concurrency Semaphore

Add `import threading` to module imports (already has `import time`).

In `__init__` signature, add `max_concurrency: int = 0` after `fallback_timeout`.
In `__init__` body, add:
```python

```

Rename `def chat_completion(...)` → `def _chat_completion_impl(...)` (private implementation).
Add new public dispatcher:
```python
def chat_completion(
    self,
    messages: List[Dict[str, str]],
    call_id: Optional[str] = None,
    temperature: Optional[float] = None,
    max_tokens: Optional[int] = None,
    response_format: Optional[Dict[str, Any]] = None,
    tools: Optional[List[Dict[str, Any]]] = None,
    output_schema: Optional[Dict[str, Any]] = None,
    timeout: Optional[int] = None,
) -> Dict[str, Any]:
    """Chat completion with optional concurrency gate (max_concurrency semaphore).

    Delegates to _chat_completion_impl(). When max_concurrency > 0, blocks until
    a concurrency slot is available (up to 300s), then releases on completion.
    """
    if self._semaphore is not None:
        if not self._semaphore.acquire(timeout=300):
            raise LLMError(
                "LLM concurrency slot unavailable after 300s "
                f"(max_concurrency={self._semaphore._value if hasattr(self._semaphore, '_value') else '?'})"
            )
        try:
            return self._chat_completion_impl(
                messages, call_id=call_id, temperature=temperature, max_tokens=max_tokens,
                response_format=response_format, tools=tools, output_schema=output_schema,
                timeout=timeout,
            )
        finally:
            self._semaphore.release()
    return self._chat_completion_impl(
        messages, call_id=call_id, temperature=temperature, max_tokens=max_tokens,
        response_format=response_format, tools=tools, output_schema=output_schema,
        timeout=timeout,
    )
```

In `create_llm_client_from_config()`, add to the `LLMProviderClient(...)` call:
```python
max_concurrency=llm_cfg.get("max_concurrency", 0),
```

## Failure modes

1. **Thread safety violation in session init** — Detection: `ResourceWarning` or `RuntimeError` under
   concurrent load. Resolution: double-checked locking (`if _session is None` → lock → `if _session is None`)
   prevents this. Link: Guarantee E (hermetic execution).

2. **Retry-After header missing or non-numeric** — Detection: `ValueError` on `float()` call.
   Resolution: `except ValueError: pass` falls through to existing error-raise behavior. No regression.
   Link: specs/21_worker_contracts.md §LLM error handling.

3. **Semaphore deadlock (acquire never released)** — Detection: W5 page generation stalls for >300s.
   Resolution: `try/finally` in dispatcher ensures `release()` always called, even on exception.
   Timeout of 300s raises `LLMError` to surface the issue. Link: specs/34_strict_compliance_guarantees.md
   Guarantee E.

4. **Pool exhaustion under high parallelism** — Detection: `ConnectionError` or `requests.exceptions.ConnectionError`.
   Resolution: `pool_maxsize=20` (higher than `max_concurrency: 8` max expected). If this fires,
   increase `pool_maxsize`. Link: specs/25_frameworks_and_dependencies.md.
