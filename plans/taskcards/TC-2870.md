# Taskcard TC-2870 — Enable multi-pass generation prevention engine (schema-config alignment)

## Objective
Make `multi_pass_generation` (and two other Round 12 fields: `incremental`, `prompt_library_path`)
valid schema-accepted `run_config` fields so that W5 multi-pass can be activated via pilot configs
without schema validation errors, and wire config-driven temperatures so pilots can run deterministically at 0.0.

- `specs/21_worker_contracts.md` — W5 Multi-Pass Generation Contract

- `specs/schemas/run_config.schema.json` — Config schema (additionalProperties: false)
- `specs/03_product_facts_and_evidence.md` — Incremental claim management

## Scope
### In scope
- Add `multi_pass_generation`, `incremental`, `prompt_library_path` to run_config schema

- Update docs/reference/config.md with multi_pass_generation section

### Out of scope

## Failure modes

### Schema rejects multi_pass_generation in pilot configs
Detection: `scripts/validate_schemas.py` fails or config dry-run exits non-zero. Resolution: Verify schema property definition matches config YAML structure exactly. Spec link: specs/schemas/run_config.schema.json additionalProperties constraint.

### Existing temperature test breaks (0.3/0.1/0.3 expectations)
Detection: pytest failure in test_llm_called_with_correct_temperatures. Resolution: Existing test should still pass because no temp overrides in config means fallback defaults 0.3/0.1/0.3. Spec link: specs/21_worker_contracts.md temperature hardening section.

### multi_pass.py crashes when run_config is not a dict (MockRunConfig)
Detection: TypeError in __init__ when accessing .get() on non-dict. Resolution: Temperature vars set in else branch with hardcoded defaults. Spec link: TC-2376 structured output envelope feature flags.
