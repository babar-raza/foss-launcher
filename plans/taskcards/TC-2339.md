## Objective

Add an LLM score verification layer to W7 ContentReviewer. After deterministic scoring, the LLM reviews scores against actual content, can downgrade routing decisions (PASS to NEEDS_CHANGES, NEEDS_CHANGES to REJECT), and detects edge cases that deterministic checks miss. LLM cannot override REJECT to PASS (safety constraint).

## Required spec references

- specs/21_worker_contracts.md: W7 ContentReviewer worker contract
- G3 directive: LLM Score Verification

## Scope

### In scope

- New prompt template `score_verifier.txt`
- New function `verify_scores_with_llm()` in scoring.py
- Integration in worker.py after deterministic scoring
- Safety constraint: LLM cannot override REJECT to PASS
- Edge case detection appended as info-level issues
- `llm_verification` field added to review_report

### Out of scope

- LLM regen agents (TC-2341)
- Deterministic check changes
- W5 generator changes

## Inputs

- Dimension scores from deterministic scoring
- All issues from check modules
- Deterministic routing status (PASS/NEEDS_CHANGES/REJECT)
- Draft content samples (first 500 chars of up to 5 files)
- LLM client (optional; skipped if unavailable)

## Outputs

- `llm_verification` dict in review_report with: llm_status, llm_scores, edge_cases, agreement, override_reason
- Potentially adjusted overall_status (downgrades only)
- Edge case issues appended to all_issues

## Failure modes

1. **LLM call fails**: Detection: exception caught in try/except. Mitigation: return None, pipeline continues with deterministic scores only. Resolution: graceful degradation by design.
2. **LLM returns invalid JSON**: Detection: json_match regex fails. Mitigation: return None, log warning. Resolution: regex is conservative, extracts only valid JSON with expected keys.
3. **LLM attempts REJECT to PASS override**: Detection: safety constraint in worker.py. Mitigation: code explicitly blocks REJECT to PASS transitions. Resolution: safety invariant enforced regardless of LLM response.
