## Objective

Add `best_practice` as a new claim kind in `classify_claim_kind()`. Claims containing best practice indicators ("recommended", "avoid", "always use") should be classified as `best_practice` instead of the default `feature`, enabling W4/W5 to route them to appropriate page types.

## Required spec references

- specs/04_claims_compiler_truth_lock.md (Claim structure and classification)
- specs/03_product_facts_and_evidence.md (Claims extraction algorithm)

## Scope

### In scope

- Add `best_practice` detection logic in `classify_claim_kind()`
- Strong keyword matching (single keyword sufficient)
- Weak keyword matching (2+ keywords required)
- Unit tests for classification accuracy

### Out of scope

- Changes to W4 routing or W5 content generation
- Changes to claim grouping logic
- Modifying existing claim kind categories

## Inputs

- Claim text strings passed to `classify_claim_kind()`

## Outputs

- Updated `classify_claim_kind()` returning `"best_practice"` for matching claims
- Unit tests validating classification accuracy

## Allowed paths

- `src/launch/workers/w2_facts_builder/extract_claims.py`
- `tests/unit/workers/test_tc_411_extract_claims.py`
- `plans/taskcards/TC-2335.md`

## Implementation steps

1. In `classify_claim_kind()`, add best practice detection before the final `return "feature"` at line 281
2. Define strong keywords: "best practice", "recommended", "avoid", "never", "always use"
3. Define weak keywords: "prefer", "instead of", "rather than", "should not", "guideline", "tip"
4. Return `"best_practice"` if any strong keyword matches, or if 2+ weak keywords match
5. Add parametrized unit tests

## Failure modes

1. **Conflict with limitation detection**: "avoid" could overlap with limitation patterns. Mitigation: limitation check runs first (line 155), so "does not support" is caught before best_practice check.
2. **False positive on workflow claims**: "recommended" in install instructions. Mitigation: workflow check at line 188 runs before best_practice, so "recommended to install" is caught as workflow first.
3. **Weak keyword threshold too low**: Single weak keyword might false-positive. Mitigation: weak keywords require 2+ matches, reducing false positives significantly.
