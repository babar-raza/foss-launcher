## Objective

Register a dedicated `api_reference` generator that produces class tables by category with usage snippets. Parameters in tables, not raw dumps.

## Required spec references

- specs/07_section_templates.md: Page role definitions

## Scope

- Create api_reference.txt prompt
- Add generate_api_reference_content() and helpers
- Register with aliases=["api_ref"]

## Inputs

- product_facts with claims and api_surface_summary
- snippet_catalog with code examples

## Outputs

- Markdown with class tables, usage snippets
- Parameters formatted as tables

## Allowed Paths

- `src/launch/workers/w5_section_writer/generators/content_generators.py`
- `src/launch/workers/w5_section_writer/generators/__init__.py`
- `src/launch/workers/w5_section_writer/prompts/api_reference.txt`
- `tests/unit/workers/test_tc_440_section_writer.py`
- `plans/taskcards/TC-2332.md`

## Implementation Steps

1. Create api_reference.txt prompt
2. Add _format_api_surface() helper
3. Add generate_api_reference_content() function
4. Add _build_deterministic_api_reference() fallback
5. Register in __init__.py
6. Add unit tests

## Failure Modes

1. Raw parameter dumps -> prompt explicitly forbids them
2. No API surface data -> fallback uses claims instead
3. Empty class table -> fallback generates bullet list
