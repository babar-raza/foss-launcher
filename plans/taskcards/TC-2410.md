## Objective

Add structured observability, in-memory counters, a maintenance CLI, and
regression-proof instrumentation tests for the LLM disk cache introduced in
TC-2409.  The goal is to make cache behavior fully transparent to operators and
tests without modifying the cache's functional logic.

## Required spec references

- `specs/10_determinism_and_caching.md` — deterministic decoding, prompt hashing
- `specs/11_state_and_events.md` — LLM call telemetry
- `docs/reference/config.md` — existing LLM Disk Cache section (extended by this TC)
- `src/launch/workers/_shared/llm_response_validator.py` — standalone helper pattern to follow

## Scope

### In scope

- New standalone module `src/launch/workers/_shared/cache_telemetry.py`:
  - `CACHE_OUTCOMES` / `CACHE_REASONS` frozensets
  - `CacheEvent` dataclass
  - `emit_cache_event(logger, outcome, reason, ...)` — non-fatal, increments counters
  - `get_cache_stats() -> Dict[str, int]` — thread-safe snapshot
  - `reset_cache_stats()` — for test isolation
- Minimal hook in `src/launch/clients/llm_provider.py` (6 lines):
  - 1 new import
  - 4 replaced `logger.debug` cache calls (hit, miss, saved, bypass_nondet)
  - 1 new `bypass/fallback` log in the currently-unlogged `else` branch
  - All changes marked `# LLM_CACHE_TELEMETRY_HOOK`
- New CLI `scripts/llm_cache_maintenance.py`:
  - `stats` — print file count, total size, oldest/newest
  - `purge` — delete all cache files (with `--dry-run`)
  - `purge-old --days N` — delete files older than N days (with `--dry-run`)
  - No external deps; Windows encoding fix applied
- New test file `tests/unit/clients/test_cache_telemetry.py` (8 test classes)
- Diagnostics subsection appended to `docs/reference/config.md`

### Out of scope

- Structured event emission to `events.ndjson` (overkill for a cache utility)
- Cache expiration / TTL enforcement (scope for a future TC)
- In-memory L2 caching (out of scope per TC-2409)

5. **Append diagnostics doc** — "Diagnosing cache behavior" subsection with outcome/reason

## Failure modes

### FM-1: `emit_cache_event` exception propagates into pipeline
- **Detection**: All code inside `emit_cache_event` is wrapped in `try/except Exception`
- **Resolution**: Exception is swallowed; counter may not be incremented but pipeline continues
- **Spec link**: Non-fatal by design (same pattern as `llm_response_validator.py`)

### FM-2: Counter race condition under parallel W5 page writing
- **Detection**: `_COUNTER_LOCK` (threading.Lock) guards all reads and writes
- **Resolution**: Thread-safe by construction; tested with 50 concurrent threads
- **Spec link**: W5 parallel execution (TC-2362)

### FM-3: Circular import between `cache_telemetry` and `llm_provider`
- **Detection**: `cache_telemetry.py` imports ONLY stdlib — no imports from `clients/` or `workers/`
- **Resolution**: Import direction is one-way: `llm_provider` → `cache_telemetry`
- **Spec link**: Standalone module pattern (follows `llm_response_validator.py`)
