## Objective

Add an opt-in disk-backed LLM response cache to `LLMProviderClient` so that
identical requests (same model + messages + decoding params + response_format +
tools) are served from disk on reruns, `launch resume` restarts, and iterative
gate-fix cycles — without incurring network latency or LLM token costs.

The cache is **disabled by default** (zero behavioural change). It is enabled
exclusively via the `FOSS_LAUNCHER_LLM_CACHE=1` environment variable.

## Implementation steps

1. **Create `llm_cache.py`** with five public functions:
   - `cache_enabled()` — reads `FOSS_LAUNCHER_LLM_CACHE`
   - `cache_dir(run_dir)` — env override > run_dir/cache/llm > .cache/llm
   - `make_cache_key(request_sig)` — SHA-256 of `json.dumps(..., sort_keys=True, separators=(",",":"))`
   - `load(key, dir_)` — returns `response` dict or `None`; corruption-tolerant
   - `save(key, response, dir_)` — atomic via temp-file + `os.replace`

2. **Integrate in `llm_provider.py`** (`_chat_completion_impl`):
   a. Move `request_payload` construction before `with LLMTelemetryContext(...)`.
   b. Call `_build_cache_context(request_payload, effective_temperature)` → `(_cache_key, _cache_d)`.
   c. If key is not None: try `_llm_cache.load(key, d)` → if hit, return early with `cache_hit=True`.
   d. After response: if key is not None and endpoint policy satisfied, call `_llm_cache.save(key, result, d)`.

3. **Add `_build_cache_context()`** method to `LLMProviderClient`.

4. **Write unit tests** covering: hit, miss, nondet bypass, ALLOW_NONDET, fallback bypass,
   CACHE_FALLBACK, corruption tolerance, default-off.

5. **Add doc section** to `docs/reference/config.md`.

## Failure modes

### FM-1: Corrupted cache file causes exception propagation
- **Detection**: `load()` catches all exceptions and returns `None`
- **Resolution**: Any `json.loads` error, missing key, or I/O error returns `None` (miss)
- **Spec link**: Corruption-tolerant read (constraint #3)

### FM-2: Cache key collision (SHA-256 truncation or collision)
- **Detection**: SHA-256 full 64-char key — collision probability negligible for pipeline scale
- **Resolution**: N/A for pipeline use; add `meta.model` check to `load()` if needed in future
- **Spec link**: Constraint #2 (key must cover all output-affecting inputs)

### FM-3: Disk full causes `save()` to fail mid-write
- **Detection**: `os.replace` will raise `OSError`; the exception propagates from `save()`
- **Resolution**: Cache save is best-effort; caller should catch or the `tmp` file is left behind
  (negligible size). The pipeline continues normally since save is outside the critical path.
- **Spec link**: Constraint #3 (atomic write prevents partial reads)

### FM-4: Fallback response mistakenly served to primary callers
- **Detection**: `_build_cache_context` / cache save only for primary endpoint (unless CACHE_FALLBACK=1)
- **Resolution**: `endpoint_used` field is stored in cache meta; `save` policy checked at write time
- **Spec link**: Constraint #5 (don't cache fallback results by default)

### FM-5: Temperature > 0 stochastic responses cached across runs
- **Detection**: `_build_cache_context` returns `(None, None)` when `temperature != 0.0` and `ALLOW_NONDET != 1`
- **Resolution**: Cache bypassed entirely for non-deterministic requests; logged at DEBUG level
- **Spec link**: Constraint FOSS_LAUNCHER_LLM_CACHE_ALLOW_NONDET flag
