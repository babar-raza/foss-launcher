## Objective

Add `build_*_context()` functions for the 13 generator roles that currently lack them. These context
builders provide role-ranked claims and relevant snippets as structured dicts for each generator's
LLM prompt, enabling per-role content prioritization.

**Note**: Check TC-2340 ("W5 silent fallback warning + generic prompt hardening") scope first to
avoid conflicting modifications to `content_generators.py`.

## Background

TC-2369 (Done) added context builders for 3 roles: `tutorial`, `feature_showcase`, `api_reference`.
The remaining 13 roles use generic claim selection. This causes poor content — e.g., troubleshooting
pages include feature claims instead of error/limitation claims; workflow pages mix claim kinds
without step ordering.

Reference: context-generator `context_merger.py:9` — `PRECEDENCE = {"extra":100,"docs":80,"api":40}`

## Governance (spec first)

Before code changes, amend `specs/07_section_writer.md` to add:

> Every `generate_*_content()` function MUST have a corresponding
> `build_*_context(page, product_facts, snippet_catalog) -> dict` function.
> The dict MUST include: `claims` (list, role-priority ranked), `snippets` (list, ≤5),
> `claim_context` (str), `snippet_text` (str).

## Implementation

### Step 1: Read existing context builders

Read `src/launch/workers/w5_section_writer/generators/content_generators.py` and study:
- `build_tutorial_context()` — the reference implementation (workflow/feature claims first)
- `build_feature_showcase_context()` — primary claim demo snippets preferred
- `build_api_reference_context()` — api/format claims sorted alphabetically

Understand the helper functions used: `_rank_claims_by_kind()`, `_get_demo_snippets()`,
`_format_claim_context()`, `_format_snippet_text()`. These MUST be reused — do not duplicate.

### Step 2: Implement 13 new context builders

Add each function using the pattern from `build_tutorial_context()`. Claim-kind priorities:

| Role | Primary claim kinds | Snippet strategy |
|------|--------------------|--------------------|
| `comprehensive_guide` | workflow → feature → api | demo_snippet_ids from top 5 workflow claims |
| `troubleshooting` | error → limitation → format | Snippets demonstrating fixes |
| `blog` | feature → workflow | First demo_snippet_id |
| `feature_blog` | feature → workflow | First demo_snippet_id |
| `performance` | limitation → feature | Snippets with timing/benchmark tags |
| `faq` | feature → api → format | No snippets required (return empty) |
| `best_practices` | workflow → limitation | Step-linked snippets |
| `getting_started` | workflow (install source_section first) → feature | Ordered install snippets |
| `workflow_page` | workflow in source_section order | Step-ordered snippets |
| `landing` | feature (top 5 only) | Hero snippet from demo_snippet_ids |
| `format_conversion` | format → api | Input/output format snippets |
| `howto_article` | workflow ordered | Step-linked snippets |
| `toc` | (none — structural) | (none — return empty) |

**Reference pattern** (reuse helpers, do NOT copy-paste — call the same helper functions):
```python
def build_comprehensive_guide_context(page, product_facts, snippet_catalog):
    all_claims = product_facts.get("claims", [])
    priority_kinds = ["workflow", "feature", "api"]
    ranked = _rank_claims_by_kind(all_claims, priority_kinds, page)
    snippets = _get_demo_snippets(ranked[:5], snippet_catalog, max_snippets=5)
    return {
        "claims": ranked,
        "snippets": snippets,
        "claim_context": _format_claim_context(ranked[:10]),
        "snippet_text": _format_snippet_text(snippets),
    }
```

### Step 3: Add context precedence system

After all 16 builders exist, add a dispatch function that returns the right context builder:

```python
_CONTEXT_BUILDERS = {
    "tutorial": build_tutorial_context,
    "api_reference": build_api_reference_context,
    "feature_showcase": build_feature_showcase_context,
    "comprehensive_guide": build_comprehensive_guide_context,
    "troubleshooting": build_troubleshooting_context,
    # ... all 16 roles
}

def get_context_for_role(page_role: str, page, product_facts, snippet_catalog) -> dict:
    """Get role-appropriate context dict. Falls back to tutorial context if role unknown."""
    builder = _CONTEXT_BUILDERS.get(page_role, build_tutorial_context)
    return builder(page, product_facts, snippet_catalog)
```

### Step 4: Wire into existing generators

For each `generate_*_content()` function that doesn't already call a context builder:
1. Add a call to `get_context_for_role(page.get("page_role","default"), page, product_facts, snippet_catalog)`
2. Use `ctx["claims"]` and `ctx["snippets"]` in the LLM prompt instead of raw claim lists
