# Taskcard TC-1619 — Troubleshooting & FAQ Extraction

## Objective

Extract 15-20 troubleshooting entries and 10-15 FAQ entries from source code error messages, expanded limitation claims, README FAQ sections, and test file docstrings to improve knowledge base article sufficiency from 15% to 50%.

## Problem Statement

**Current Problem**: 15% KB sufficiency — only 15 limitation claims, no troubleshooting/FAQ/error resolution content

The facts builder currently extracts limitations ("not yet supported") but misses:
- Error messages in code (ValueError, TypeError, custom exceptions)
- Known issues and workarounds
- FAQ sections in READMEs
- Troubleshooting guidance from test files

This leaves KB articles without support content for users encountering issues.

## Required Spec References

- specs/03_product_facts_and_evidence.md - Claims extraction algorithm
- specs/04_claims_compiler_truth_lock.md - Claim structure and ID generation
- specs/21_worker_contracts.md:98-125 - W2 FactsBuilder contract
- specs/schemas/evidence_map.schema.json - Claim schema structure

## Scope

### In Scope

1. Extract error messages from raise statements in source code
2. Extract custom Exception class definitions
3. Expand limitation claim patterns beyond "not yet supported"
4. Extract FAQ entries from README FAQ sections (Q&A format)
5. Synthesize FAQ entries from test function names and docstrings
6. Add 5 new unit tests covering all extraction patterns

### Out of Scope

- LLM-based FAQ generation (hallucination risk)
- Parsing non-Python error messages
- Extracting from compiled/binary files
- GUI-based troubleshooting guides
- Video tutorial extraction

## Inputs

- Source code files (.py) with raise statements and Exception classes
- README.md files with FAQ/Troubleshooting sections
- Test files with descriptive function names and docstrings
- Existing limitation claims from extract_claims.py

## Outputs

- 15-20 troubleshooting claim entries with error_type metadata
- 10-15 FAQ claim entries with question/answer structure
- Expanded limitation claims (known issues, workarounds, compatibility)
- 5 new passing unit tests
- Updated claims in product_facts.json for both pilots

### Step 1: Add Error Message Extraction (60 mins)

**File**: `src/launch/workers/w2_facts_builder/extract_claims.py`

Add new function `_extract_error_messages()` at line ~1250 (after `deduplicate_claims`):

```python
def _extract_error_messages(code_content: str, source_file: str) -> List[Dict]:
    """Extract error messages from raise statements and Error classes.

    Patterns:
    - raise ValueError("error message")
    - raise CustomError(f"error {variable}")
    - class CustomError(Exception): ...

    Args:
        code_content: Python source code
        source_file: Source file path

    Returns:
        List of troubleshooting claim dicts with error context
    """
```

Implement two regex patterns:
1. Raise statements: `r'raise\s+(\w+)\s*\(\s*[\'"]([^\'"]+)[\'"]'`
2. Exception classes: `r'class\s+(\w+Error)\s*\([^)]*Exception[^)]*\):'`

## Failure Modes

### Failure Mode 1: False positives (code as error messages)

**Detection**: High claim count with gibberish text
**Resolution**: Apply existing `_is_code_like()` filter to error message text
**Spec**: specs/03_product_facts_and_evidence.md (quality filters)
**Gate**: Unit test `test_error_message_extraction_filters_code_snippets()`

### Failure Mode 2: FAQ extraction too strict (low recall)

**Detection**: FAQ claim count < 10 in pilots
**Resolution**: Lower prose threshold from 30 words to 20 words
**Spec**: specs/03_product_facts_and_evidence.md (minimum claim length)
**Gate**: Pilot verification checks FAQ count >= 10

### Failure Mode 3: Test file parsing errors

**Detection**: Exception during `_extract_faq_from_tests()`
**Resolution**: Wrap in try/except, log warning, continue processing
**Spec**: specs/21_worker_contracts.md (graceful degradation)
**Gate**: Unit test `test_faq_from_tests_handles_syntax_errors()`

### Failure Mode 4: Duplicate claims across sources

**Detection**: High duplicate count in deduplicate_claims()
**Resolution**: Use existing claim_id deduplication (same claim_text + claim_kind)
**Spec**: specs/04_claims_compiler_truth_lock.md (stable IDs)
**Gate**: Existing deduplicate_claims() logic

### Failure Mode 5: Error messages with variables (f-strings)

**Detection**: Error messages like "Error: {variable}" extracted literally
**Resolution**: Accept literal text (template variables are valid error patterns)
**Spec**: specs/03_product_facts_and_evidence.md (claim text normalization)
**Gate**: Unit test `test_error_message_extraction_fstring_preserved()`
