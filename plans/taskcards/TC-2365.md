## Objective

Add `source_section` metadata to every extracted claim in W2. This is the normalized
slug of the Markdown heading under which the claim sentence appeared. When W4 assigns
claims to pages, this field allows section-matched assignment rather than keyword-based
bucket guessing.

**Root cause (RCA H5)**: All claims from "Installation" and "Advanced Features" sections
are currently treated identically — no structural metadata survives extraction.

## Required spec references

- `specs/03_product_facts_and_evidence.md` §"Claims extraction algorithm"
- `C:\Users\prora\.claude\plans\reactive-weaving-clock.md` §H5, §S-1, §Part 4-A

## Scope

### In scope

- Modify `extract_candidate_statements_from_text()` in
  `src/launch/workers/w2_facts_builder/extract_claims.py`:
  - Add a pre-pass that builds a line→heading map using a Markdown heading parser
  - For each extracted candidate, look up the heading at `start_line` and set
    `source_section` = slugified heading text (or `""` if no heading above)
- Modify `extract_structured_sections_from_readme()`: already passes `section_heading`
  through `_extract_section_claims`; ensure `source_section` is set there too.
- Add 4 unit tests in `tests/unit/workers/test_tc_411_extract_claims.py`

### Out of scope

- Changing claim_id computation (source_section must NOT change the SHA256 hash)
- Modifying W4 to use source_section (that is TC-2366)
- Changing the claim schema JSON (source_section is an optional additive field)

## Inputs

- `text: str` — full file text
- `file_path: Path`, `repo_dir: Path` — unchanged

## Outputs

Each candidate claim dict gains:
- `source_section: str` — slugified heading (e.g., `"getting-started"`, `"installation"`)
  or `""` if the claim appears before any heading

## Implementation steps

1. Add helper `_build_heading_map(lines: List[str]) -> Dict[int, str]`:
   ```python
   def _build_heading_map(lines: List[str]) -> Dict[int, str]:
       """Map each line number to the slug of the nearest heading above it."""
       heading_map: Dict[int, str] = {}
       current_heading_slug = ""
       in_code_block = False
       for line_num, line in enumerate(lines, start=1):
           stripped = line.strip()
           if stripped.startswith("```"):
               in_code_block = not in_code_block
           if not in_code_block:
               m = re.match(r"^#{1,3}\s+(.+)$", stripped)
               if m:
                   current_heading_slug = re.sub(r"[^a-z0-9]+", "-",
                                                  m.group(1).strip().lower()).strip("-")
           heading_map[line_num] = current_heading_slug
       return heading_map
   ```

2. At the top of `extract_candidate_statements_from_text()`, before the candidate loop,
   call `heading_map = _build_heading_map(text.split('\n'))`.

3. When appending each candidate (both sentence and bullet passes), add:
   ```python
   'source_section': heading_map.get(start_line, ""),
   ```

4. In `extract_structured_sections_from_readme()` and `_extract_section_claims()`,
   set `source_section` to the slugified `section_heading` argument:
   ```python
   'source_section': re.sub(r"[^a-z0-9]+", "-",
                             section_heading.lower()).strip("-") if section_heading else "",
   ```

5. Add 4 unit tests:
   - `test_source_section_set_for_sentence_under_heading`: a sentence after `## Installation`
     gets `source_section="installation"`
   - `test_source_section_empty_before_any_heading`: a sentence before the first heading
     gets `source_section=""`
   - `test_source_section_set_for_bullet_under_heading`: bullet under `## Features` gets
     `source_section="features"`
   - `test_source_section_does_not_affect_claim_id`: same claim with different source_section
     still has the same `claim_id` (SHA256 unchanged)

## Acceptance criteria

- All existing W2 tests still pass
- 4 new tests pass
- `source_section` is present on all candidate dicts from both code paths
- `claim_id` is unchanged by this addition (SHA256 inputs: `normalized_text|claim_kind` only)
