## Objective

W2 enrichment batches took 180–296s each in pilot runs despite `request_timeout_s: 120`.

**Root cause**: `request_timeout_s: 120` IS enforced at HTTP level, but primary and fallback
both point to the same local Ollama instance. When primary times out at 120s, the fallback
immediately tries the same overloaded server for another 120s → total 240s per batch. The
`null finish_reason` is Ollama returning a truncated response on fallback, not a connection error.

**Fix**: Add `enrich_timeout_s` config key so W2 enrichment calls use a shorter per-call timeout
(e.g. 60s) independently of the global `request_timeout_s` (which may be set higher for
page-generation calls that need more time).

**Immediate workaround (no code required)**: reduce `request_timeout_s: 120` → `60` in
pilot pinned configs to cap primary + fallback ≤ 120s total.

## Scope

### In scope
- `src/launch/workers/w2_facts_builder/enrich_claims.py`:
  - `enrich_claims_batch()`: add `timeout: Optional[int] = None` param; pass to `chat_completion()`
  - `enrich_claim_text_batch()`: same
- `src/launch/workers/w2_facts_builder/worker.py`:
  - Read `_enrich_timeout = run_config.get("enrich_timeout_s", None)`
  - Pass `timeout=_enrich_timeout` to both batch functions
- `specs/schemas/run_config.schema.json`: add `enrich_timeout_s` property

### Out of scope
- Pilot config changes (handled separately as config fix, not a code TC)
- `llm_provider.py` (no change needed — already supports per-call `timeout=`)

### `worker.py` change

```python

    timeout=_enrich_timeout,
```
