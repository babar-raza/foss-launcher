## Implementation steps

### R17-008 + R17-009: Rewrite FAQ prompt
1. Replace [faq.txt](../../src/launch/workers/w5_section_writer/prompts/faq.txt) with new structure:
   ```
   You are a technical writer creating an FAQ page for {product_name}.

   Write a well-organized FAQ page that directly answers common developer questions.

   ## Source Material
   {enriched_claims}
   {snippets}

   ## CRITICAL Rules
   1. **NEVER redirect to documentation**. Do NOT write answers like "See the documentation".
      Every answer must contain the ACTUAL answer with specific details.
   2. **Include code** in at least 40% of answers. Show code inline.
   3. **Link to related pages** for deeper reading:
      - Getting started: [Getting Started Guide](../getting-started/)
      - Installation: [Installation Guide](../installation/)
      - Troubleshooting: [Troubleshooting Guide](../../kb/troubleshooting/)
      - API details: [API Reference](../../reference/api-overview/)
      But the answer itself must be self-contained — the link is supplementary.

   ## Format
   1. Organize into categories: Getting Started, Common Tasks, Troubleshooting, Advanced
   2. Each Q&A:
      ### Q: [Specific question]?
      A: [2-5 sentence answer with concrete details]
   3. Reference claims using [claim: CLAIM_ID] markers
   4. Minimum 12 Q&A pairs
   5. Each answer must be at least 3 sentences with specifics

   ## Output Format
   Return only the markdown content. Do not include frontmatter or the page title (H1).
   ```

### R17-003: Getting-started generator
1. Create `generate_getting_started_content()` in [content_generators.py](../../src/launch/workers/w5_section_writer/generators/content_generators.py):
   - Extract install_steps claims
   - Build pip install code block
   - Extract first workflow or example
   - Build "hello world" code block
   - Structure: Prerequisites → Installation (with code) → First Example (with code) → Next Steps
   - Minimum 2 code blocks required

2. Register in [__init__.py](../../src/launch/workers/w5_section_writer/generators/__init__.py):
   ```python
   GENERATOR_REGISTRY.register(
       "getting_started", generate_getting_started_content,
       aliases=["getting-started", "quickstart"],
       description="Getting started guide with code examples",
   )
   ```

3. Update W4 to assign `page_role="getting_started"` for getting-started pages

### R17-004: Bullet formatting rules
1. In [worker.py](../../src/launch/workers/w5_section_writer/worker.py) `_build_section_prompt()` line ~1231:
   ```python
   "",
   "## Bullet and List Formatting Rules",
   "- Use bullet points (- item) for lists of 3+ related items",
   "- Use numbered lists (1. step) ONLY for sequential steps where order matters",
   "- Never write lists as run-on paragraphs",
   "- Each bullet point should be a single, complete thought",
   ```

### R17-012: Full API surface for reference pages
1. In [w4_ia_planner/worker.py](../../src/launch/workers/w4_ia_planner/worker.py) line ~1850:

## Failure modes
### FM1: Getting-started generator produces prose-only output
Detection signal: Generated getting-started pages have zero code blocks.
Resolution steps: Enforce minimum 2 code blocks in generator logic with fallback snippets.
Spec/Gate link: specs/05_example_curation.md (code snippet requirements)

### FM2: FAQ answers still redirect to docs
Detection signal: Manual inspection reveals "See documentation" or "Refer to guide" answers.
Resolution steps: Strengthen anti-redirect language in prompt with negative examples.
Spec/Gate link: plans/hazy-riding-gizmo.md R17-008 (FAQ anti-redirect requirement)

### FM3: Reference pages still limited to 5 classes
Detection signal: API overview page lists only 5 classes despite 96+ classes in API.
Resolution steps: Verify api_surface_summary is passed and used by reference generator.
Spec/Gate link: specs/21_worker_contracts.md (W5 specialized generators)
