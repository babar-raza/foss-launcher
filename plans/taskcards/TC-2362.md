## Objective

Enable W5 SectionWriter to write multiple pages concurrently using a `ThreadPoolExecutor`,
reducing wall-clock time for large pilots (e.g. 170+ pages) by 5–10x.

The approach uses a snapshot of `cross_page_summaries` taken at batch start so each page
gets its own `MultiPassOrchestrator` instance (no shared mutable state). This eliminates
the only real blocker to parallelism. Default `max_parallel_pages=1` preserves current
sequential behavior with zero impact on existing configs.

## Implementation steps

### Step 1: Extract `_generate_page()` helper

Pull the per-page generation logic from the main loop into a function:

```python
def _generate_page(
    page: dict,
    product_facts: dict,
    snippet_catalog: dict,
    llm_client,
    page_plan: dict,
    multi_pass_orchestrator,  # per-page instance (may be None)
    code_understanding: dict,
    evidence_map: dict,
    cross_page_summaries_snapshot: dict,  # frozen read-only
    run_config: dict,
    run_layout,
    drafts_dir: Path,
    run_id: str,
    trace_id: str,
    span_id: str,
) -> dict:  # returns manifest entry dict
```

The function covers lines 2009–2107 of the current loop body (generation + sanitizer + token
validation + disk write + manifest entry construction). It does NOT emit events (event emission
moves to the caller to avoid concurrent file writes).

Returns the manifest entry dict. Raises `SectionWriterUnfilledTokensError` on token failure.

### Step 2: Conditional dispatch in `run()` method

After the existing preserved-page fast-path, add:

```python
max_parallel = min(max(run_config.get("max_parallel_pages", 1), 1), 16)

if max_parallel == 1:
    # Existing sequential behavior — call _generate_page() in loop, update
    # cross_page_summaries from orchestrator after each page (unchanged logic)
    for page in to_generate:
        entry = _generate_page(page, ..., multi_pass_orchestrator, ...)
        draft_files.append(entry)
        if multi_pass_orchestrator is not None:
            cross_page_summaries = dict(multi_pass_orchestrator.cross_page_summaries)
        emit_event(...)  # EVENT_ARTIFACT_WRITTEN per page
else:
    # Parallel mode — snapshot summaries, per-page orchestrators
    cross_page_summaries_snapshot = dict(cross_page_summaries)  # frozen
    futures = {}
    with ThreadPoolExecutor(max_workers=max_parallel) as pool:
        for page in to_generate:
            orch = _make_page_orchestrator(llm_client, prompt_loader, rc)
            fut = pool.submit(_generate_page, page, ..., orch,
                              cross_page_summaries_snapshot, ...)
            futures[fut] = page
    for fut in futures:
        draft_files.append(fut.result())  # re-raises on exception
    # Emit batch event after pool completes
    for entry in draft_files:
        if entry.get("page_status") != "preserved":
            emit_event(..., EVENT_ARTIFACT_WRITTEN, {"artifact": "draft", ...})
```

`_make_page_orchestrator(llm_client, prompt_loader, rc)` creates a fresh `MultiPassOrchestrator`
seeded with `cross_page_summaries_snapshot`. Returns `None` if multi-pass is not enabled or
prompt_loader is unavailable.

### Step 3: Sort after pool completes

```python
section_order = {"products": 0, "docs": 1, "reference": 2, "kb": 3, "blog": 4}
draft_files.sort(key=lambda d: (section_order.get(d["section"], 99), d["output_path"]))
```

This is already present in the existing code; just ensure it runs after parallel collection.

### Step 4: Tests (3 required)

In `tests/unit/workers/test_tc_440_section_writer.py`:

1. **`test_parallel_pages_all_written`**: mock `_generate_page` to return a manifest entry,
   call with `max_parallel_pages=4` and 8 mock pages → verify all 8 entries in `draft_files`,

2. **`test_parallel_default_sequential_behavior`**: `max_parallel_pages=1` (or absent) →

3. **`test_parallel_exception_propagates`**: one page raises `SectionWriterUnfilledTokensError` →

## Failure modes

1. **LLM client not thread-safe** — Detection: timeout or connection errors in parallel mode.
   Resolution: set `max_parallel_pages=1` in run_config to fall back to sequential.
   Spec/gate: none (graceful degradation).

2. **Exception in page worker swallowed** — Detection: missing pages in `draft_manifest.json`.
   Resolution: `fut.result()` re-raises, so exception propagates to W5 caller → pipeline fails.
   Spec/gate: `WORK_ITEM_FAILED` event emitted.

3. **`max_parallel_pages` out of range** — Detection: ValueError if not clamped.
   Resolution: clamp to [1, 16] via `min(max(value, 1), 16)` before use.
   Spec/gate: specs/21_worker_contracts.md §"Parallel Page Writing".
