## Objective

Fix stale scores in W7 review report. Currently, LLM regen agents run AFTER the report is written, meaning the report contains pre-regen scores. Restructure worker.py to: (1) run LLM regen BEFORE report writing, (2) re-run all checks after LLM modifications, (3) re-score and re-route, (4) write report with final scores.

## Required spec references

- specs/21_worker_contracts.md: W7 ContentReviewer worker contract

## Scope

### In scope

- Restructure worker.py lines 286-376: move LLM regen before report writing
- Re-run all 4 check dimensions after LLM modifications
- Re-calculate scores and re-route after LLM regen
- Move post-LLM sanitization after regen but before report
- Write report with final (post-regen) scores

### Out of scope

- Changes to check modules
- Changes to scoring rubric
- Changes to auto-fix logic

## Inputs

- Draft files modified by LLM regen agents
- Check module results (content_quality, technical_accuracy, usability, semantic_accuracy)

## Outputs

- review_report.json with accurate post-LLM scores
- Correct overall_status reflecting post-regen content state

## Allowed paths

- `src/launch/workers/w7_content_reviewer/worker.py`

## Implementation steps

1. After `overall_status = route_review_result(...)`, add TC-2339 LLM verification block
2. Move LLM regen (`spawn_enhancement_agents`) BEFORE report writing
3. After regen, if any files modified, re-run all checks, re-score, re-route
4. Move post-LLM sanitization after regen
5. Re-compute severity counts and page status from final issues
6. Build review report with final scores, including agent_results and llm_verification
7. Write report to disk

## Failure modes

1. **LLM regen fails silently**: Detection: agent_results show files_modified=0. Mitigation: re-check only triggered when files_modified > 0. Resolution: report reflects original scores (correct behavior when regen produces no changes).
2. **Re-check introduces new issues not in original**: Detection: post-LLM score may be worse. Mitigation: this is correct behavior (regen may introduce issues). Resolution: scores accurately reflect content state.
3. **Performance regression from double-checking**: Detection: wall-clock time increase. Mitigation: re-check only runs when files were actually modified. Resolution: correctness trumps performance for quality gate.
