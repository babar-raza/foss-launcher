## Objective

Add `detect_format_conversions()` and `_cluster_claims_by_topic()` functions to extract format conversion capabilities and topic clusters from claims and API surface data. This enables W4 to generate per-format-conversion pages and per-topic how-to articles matching aspose.net content structure.

## Required spec references

- specs/03_product_facts_and_evidence.md (Claims extraction and grouping)
- specs/04_claims_compiler_truth_lock.md (Claim structure)

## Scope

### In scope

- New `detect_format_conversions(claims, api_surface)` function
- New `_cluster_claims_by_topic(claims)` helper function
- Detection of "convert X to Y" patterns in claim text
- Detection of Converter/SaveOptions/LoadOptions class names in API surface
- Topic clustering with minimum 3 claims per cluster
- Unit tests for both functions

### Out of scope

- Integration into W2 worker `run()` function (depends on downstream TC)
- Changes to W4 page planning
- Changes to product_facts schema

## Inputs

- List of claim dicts with `claim_id` and `claim_text` fields
- API surface dict with optional `classes` list

## Outputs

- `detect_format_conversions()` returning dict with `format_conversions`, `conversion_pairs`, and `how_to_clusters`
- `_cluster_claims_by_topic()` returning dict of topic -> claim_id lists
- Unit tests validating detection accuracy

## Implementation steps

1. Add `detect_format_conversions(claims, api_surface)` at module level (end of file, ~line 4271)
2. Add `_cluster_claims_by_topic(claims)` helper function
3. Implement regex-based conversion pair detection from claim text
4. Implement API class name pattern detection (Converter, SaveOptions, etc.)
5. Implement topic clustering with predefined keyword sets and minimum 3-claim threshold
6. Add unit tests for conversion detection, API matching, and clustering

## Failure modes

1. **Regex misses compound format names**: "XLSX" vs "Excel" may not match. Mitigation: regex captures word tokens; format normalization can be added later.
2. **Topic cluster keywords too broad**: "format" keyword matches too many claims. Mitigation: cluster requires 3+ claims minimum and keywords are specific to each topic.
3. **Empty API surface**: No classes provided. Mitigation: function handles empty `api_surface.get("classes", [])` gracefully.
